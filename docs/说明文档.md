# 《言出法随》作品说明文档

- 单人队伍
- 线上试玩：https://www.yanchufasui.top （电脑、手机都能打开，微信里也能玩）
- 代码仓库：https://github.com/Francis-shift/yanchufasui
- 一句话：**说一句中文就能施法的网页 3D 动作游戏。** 大模型负责听懂这句话，程序负责按规则裁决，物理引擎让结果真的发生。

---

## 一、作品是什么

傀儡大军从云海沿石阶和索桥攻上宗门山门，玩家是守山门的修士。

玩家打字或按住麦克风说出一句咒语，比如「三颗冰锥从天而降，钉住左边那几个」。游戏把这句话翻译成法术：用什么元素、什么形态、打谁、几颗、怎么飞、多大威力。之后，冰锥就真的从天上落到左边那群敌人身上。

两种模式：

- **试炼（主推）**：在山门广场上走位，和三个 boss 轮流交手，中间夹着小怪潮。
  - **寒甲傀儡王**：冰甲，只怕火。
  - **石甲巨像**：石甲，只怕雷；蓄力冲撞时猛打能打断。
  - **火灵**：火罩，只怕冰；火环留着缺口，要从缺口跑出去。
  - 一局是小怪潮和 boss 交替。每打完一段三选一：换招、学字诀、领悟融合招、学心法。字诀写进按钮咒语里才生效，例如「破」打甲翻倍、「返」让土墙把冰锥弹回去。
  - 踩着招式落下的那一瞬间闪避，算完美闪避：顿帧，回法力和精力。
- **守关**：五波敌人从两条路上来，守住身后的阵眼。每一波是一道「题」，要用合适的咒语解。

**不想打字也能玩。** 开局选三个天赋，点按钮或按键就能放招。战前可以给按钮写一句咒语，也可以让模型看着局面帮你写。写完后，这个按钮就变成这一招。

**说得越好，法术越强。** 模型会给每句话的「气势」打 0～3 档。档位越高，伤害越高、特效越大。气势攒满八格，就能召唤龙。火、冰、雷、风、土五条龙，各有各的飞法和落地效果。

打完一局，可以生成一张战报卡，上面有这局念成的咒语名、最佳一击的画面和二维码，方便转发。

## 三、技术架构：模型管语义，程序管规则

```
玩家一句话（打字，或按住说话 → 语音识别成文字）
   │
   ├─ 0.1 秒内：浏览器里先按关键词猜元素，法阵变色（不等网络）
   │
   ├─ 咏唱动画（时间放慢到 0.3 倍）同时请求解析接口
   │      北京线路（火山引擎函数服务，与模型同机房）── 不通 ──> 新加坡线路（网站自带接口）
   │      大模型只输出固定格式的「法术意图」：元素、形态、目标、威力、颗数、轨迹、原词、气势、名字
   │      4.5 秒没回来 / 断网 / 额度用完 ──> 改用关键词解析，照样能玩
   │
   ├─ 清洗（game/rules/intent.js）：不在表里的选项丢掉，数值夹到上限，引用的原词必须真在原话里
   ├─ 裁决（game/rules/arbiter.js，纯函数）：法力消耗、组合打折、法力不够降级、伤害、气势、融合、召唤
   │      模型说「威力 999」也只按上限算；喊「威力无限」会触发「法则反噬」演出
   ├─ 咒语卡：书法大字写名字；原话里被听懂的词加下划线并注明变成了什么，没听懂的标灰
   └─ 执行：three.js 画面 + cannon-es 物理（冻结、灼烧、风推下悬崖、土墙挡路和挡弹幕、雷连锁）
```

**为什么这样分。** 大模型擅长听懂千变万化的说法，但它给的数字不可信，还可能被玩家「带偏」。所以模型只做翻译，而且只能填固定格式。凡是影响胜负的数字，都由程序算，并且有单元测试。

**技术栈**

- 画面：three.js（WebGL）
- 物理：cannon-es
- 网站：Next.js
- 部署：EdgeOne Makers 加自己的域名，推送即上线
- 解析模型：火山方舟上的 DeepSeek V4.1 Flash，关闭深度思考
- 语音识别：火山引擎流式语音识别 2.0
- 书法字体：按字表裁剪的开源字体
- 音效和背景音乐：在浏览器里现场合成，只有龙吟是录音

## 四、技术难点与解决办法

1. **解析太慢。**
   - 问题：网站在境外节点，跨境调国内模型，白天约一半请求超时。
   - 解决：把解析接口单独部署到国内云函数，和模型同一机房；网页先走国内线路，不通自动换回境外线路。
   - 结果：一句话从常常超过 4 秒降到约 1.1 秒（国内手机实测）。
   - 等待时间由咏唱动画遮住；关键词先猜元素，让法阵在 0.1 秒内就有反应。
2. **模型可能被带偏。**
   - 手段：模型只能输出固定格式，程序清洗、夹上限，原词必须出现在原话里。
   - 验证：用独立出题方写的 20 句攻击句检验，包括忽略规则、冒充管理员、角色扮演、塞 JSON、套提示词、数值越界、拼音繁体全角绕过、超长与空白等，全部挡住。
3. **听得懂各种说法。**
   - 出题：50 句评测咒语由独立出题方编写，涵盖口语、文言、网络用语、诗句、只描写效果不说元素名、多步组合、只差一个词的配对等。
   - 封存：题目在第一次调提示词之前就提交封存，之后一个字不改。
   - 结果：最近一次跑分（10/20）答对 49/50。
4. **断网也能玩。**
   - 浏览器里有一套关键词解析：超时、断网、额度用完时自动接管。
   - 咒语卡会注明这一句走的是哪条路。
5. **AI 生成的 3D 模型和玩法对不上。**
   - 问题：生成的牌坊又宽又矮，boss 过不去。
   - 解决：用脚本把柱身拉高，再按真实尺寸重排场景。
   - 自定格式：所有模型打包成自定的二进制格式加 gzip，带骨骼的角色去掉手指骨、压缩权重，开局后台下载；模型没到之前用方块占位。
6. **龙不能穿模。**
   - 做法：五条龙沿曲线飞行，每次召唤从备选路线里挑一条离牌坊、石兽、华表都足够远的。
   - 测试：自动测试按真实模型尺寸，核对整条路线离实心物件的距离。
7. **boss 招式要「看得见、躲得开」。**
   - 红圈、扇形、火环缺口都先在地上预警，boss 出手的动作帧正好对准红圈落下的那一刻。
   - 完美闪避的判定窗口、各招的预警时长都写成规则函数，并配有测试。
8. **公开链接防刷。** 一句最多 60 字，每人每分钟有次数上限，每天有总花费上限；超额自动切到关键词解析。玩家输入和模型起的名字都要过敏感词过滤。

## 五、质量保障

- **单元测试 229 条**（`npm test`），覆盖规则层、boss 招式判定、寻路、龙的飞行净空、防刷、墙挡弹幕等。
- **变异检验**：改坏关键代码，确认测试会变红，证明测试真能拦住错误。
- **评测集与攻击句**：独立出题、先封存再调提示词；跑分结果存在 `tests/eval/results/`。
- **画面验证**：
  - 打一个离线单文件版本，在固定场景、同一帧上截图对比。
  - 调试面板显示帧率、粒子数和上一句的解析来源与耗时。
  - 另有手机检查页，判断卡顿出在画面、特效还是物理。

## 六、人与 AI 的分工

单人参赛，开发中大量使用 AI。分工原则：要账号或密钥的、要花钱的、要对外发布的、要靠耳朵听的、要用真手机的、要当面讲的，都归本人；其余归 AI。砍什么功能、推不推送、风格好不好看、游戏好不好玩，最后都由本人定。

| 部分 | AI | 本人 |
|---|---|---|
| 全部代码（画面、规则、提示词、接口、防刷、测试、打包工具） | 编写，并配单元测试和中文注释 | 提需求、试玩、提出修改、决定取舍 |
| 玩法与设计 | 提方案、写设计文档 | 定玩法（如三个 boss、五条龙都做、墙要挡弹幕），亲手试玩并提出修改 |
| 3D 模型 | 写概念图提示词、检查尺寸、打包进游戏 | 用 Tripo 出概念图、建模、绑骨骼、挑选 |
| 评测集与攻击句 | 写出题说明 | 交给另一家厂商的模型出题，结果原样交回封存 |
| 账号、密钥、部署、域名、语音识别开通 | 说明在哪开、填什么 | 开通、充值、填环境变量 |
| 声音 | 找候选、剪辑 | 试听挑选 |
| 文字材料与视频 | 起草、写分镜、剪辑 | 审改、录屏、提交 |

过程证据：

- 仓库从 10/17 开赛第一天起有 120 多次提交，每次一件事，写清为什么。
- `docs/设计文档.md` 末尾的变更记录逐条写了改了什么、依据是什么（多为本人试玩后的反馈）。

AI 的具体使用情况见 [AI 使用声明](AI使用声明.md)。
