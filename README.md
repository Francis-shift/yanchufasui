# 言出法随

说一句中文就能施法的 3D 守关游戏。打字（之后也能说话）说出咒语，大模型听懂这句话，程序按规则裁决，物理引擎让结果真实地发生。不想打字的人，用开局选的三个天赋按钮也能玩；给按钮写一句咒（或让模型看着局面帮你写），按钮就变成这一招。

> 傀儡大军从云海里沿石阶和索桥攻上山门。你是守山门的修士，身后是护山大阵的阵眼，阵眼破了就输。

## 一句话架构：模型管语义，程序管规则

```
玩家一句话
  → 回车 0.1 秒内：关键词先猜元素，法阵变色（不等网络）
  → 咏唱（最短 0.8 秒，时间慢到 0.3 倍）同时请服务器上的模型解析
       模型只输出固定格式的"法术意图"：元素、形态、目标、威力、颗数、轨迹、来源原词、气势、名字
       4.5 秒没回来 / 断网 / 额度用完 → 改用关键词解析，照样能玩
  → 清洗（game/rules/intent.js）：枚举不在表里就丢、数值夹到上限、来源词必须真在原话里
  → 裁决（game/rules/arbiter.js，纯函数）：消耗、组合八折、法力不够就降级、伤害、气势、首次发现、融合（先风后火 = 火卷风，先火后风 = 烈焰冲击）、召唤（气势槽满才召得出冰龙，差一口气就化作冰雨）
  → 锁定：被打的敌人头上、落点地面先亮标记（亮的就是要打的）
  → 咒语卡：书法大字写名字；原话里被听懂的词加下划线并注明变成了什么，没听懂的标灰
  → 执行：弹 / 爆 / 墙 / 雨 × 火 / 冰 / 风 / 土 / 雷，冻结、灼烧、风推下悬崖、土墙挡路、雷连锁与麻痹；命中结算再走一遍规则（反应、盾牌减伤）
  → 敌人：上了广场按流场寻路，绕开香炉、华表、土墙，障碍一变就重算
```

模型说"威力 999"也只按上限算；会影响胜负的数字只在 `game/rules/` 里算，并有单元测试。

## 目录

| 位置 | 内容 |
|---|---|
| `game/rules/` | 规则层：数值表、意图清洗、关键词解析、裁决器（纯函数）、天赋与按键（默认招、两个按钮合成一句、按打法攒气势、卷轴）、内容安全（敏感词）、书法字表 |
| `game/world/` | 场景：傍晚的天空、云海、远处的石峰与楼阁；入侵进程（`invasion.js` 按波次算程度：紫黑雾从敌人来的那一侧吞掉天、云海染黑、雾里闪电、远处楼阁起火）；山门广场、石阶、索桥、阵眼（台面、台沿、台底山石在 `plaza.js`：贴图用代码画，入侵时台面裂开、烧焦）；护山大阵的金色光罩（`barrier.js`，阵眼掉血就裂）；牌坊、石兽、镇山石的模型加载（`props.js`，模型文件的读法在 `drg2.js`）；流场寻路 |
| `game/dev/` | 只给本机预览面板用的检查页（物件材质），游戏不引用 |
| `game/actors/` | 三种敌人（小傀儡、盾傀儡、巨像）：一跳一跳的程序动画、寻路、冻结、灼烧、被风推走、坠入云海、碎裂 |
| `game/fx/` | 特效：粒子、法阵、飞弹、爆炸、冰棱、法则反噬、锁定标记、墙（土墙石块 / 光幕）、融合（火卷风、烈焰冲击）、冰龙召唤（模型沿曲线游动） |
| `game/ui/` | 界面：输入框、法力与阵眼、咒语卡、浮字、开始与结算 |
| `game/main.js` | 入口：把上面接起来，施法流程、五波守关与主循环 |
| `game/check.js` | 手机检查页：自动跑三段压力测试，判断卡在画面、特效还是物理 |
| `app/` | 网站（Next.js）：游戏页、`/check` 检查页、`api/parse` 解析接口的新加坡线路（北京不通时的后备；`?diag=1` 诊断线上慢在哪） |
| `cn-func/` | 解析接口的北京线路：火山引擎函数服务的外壳（收发、跨域只认本站、来源 IP），打包后在控制台上传 |
| `public/models/` | 本人用 Tripo 生成的模型，打包成 DRG2 格式后 gzip，配 WebP 贴图：冰龙（气势槽过半才下载）；牌坊、石兽、镇山石（`tools/pack_prop.py` 打包，开局后台下载，到了替换方块占位） |
| `public/fonts/` | 按字表裁剪的书法字体（咒语名用马善政，大字用志莽行，SIL OFL 开源协议，协议原文同目录） |
| `server/` | 解析接口的核心（`parse-core.ts`，两条线路共用：解析、求灵感、预热、诊断）、提示词、防刷计数 |
| `tests/` | 单元测试（`npm test`）；`tests/eval/` 封存的评测集与攻击句、勘误、各模型跑分结果 |
| `tools/` | `build_preview.py` 打离线单文件页面验画面（`props` 打物件材质检查页；本地模块经 `strip-comments.mjs` 去掉注释，省体积）；`pack_prop.py` 把 Tripo 导出的场景物件打包成网页用的模型与贴图；`build-cn-func.mjs` 打包北京线路的函数；`bench-parse.mjs` 测解析延迟；`eval-parse.mjs` 跑评测集；`subset_font.py` 按字表裁书法字体；`name-charset.mjs` 查模型起的名字有多少落在字表里 |
| `docs/` | 设计文档、出题说明、试玩记录 |

## 本地运行

需要 Node.js 20.9 以上。

```bash
npm install
cp .env.example .env.local   # 填入火山方舟的 API Key 与模型名；不填也能玩（只走关键词解析）
npm run dev
```

打开 http://localhost:3000 。按 <kbd>`</kbd> 打开调试面板（帧率、粒子数、上一句的解析来源与耗时）。

```bash
npm test                       # 规则层与防刷的单元测试
npm run build                  # 生产构建
python tools/build_preview.py  # 生成 preview/index.html（离线单文件，只走关键词解析）
```

## 部署

线上地址：https://www.yanchufasui.top （国内手机流量、微信内都能打开）。

部署在 EdgeOne Makers（原名 Pages；加速区域选"全球可用区（不含中国大陆）"，免备案）+ 自己的域名，推送到 main 即自动构建；同一仓库接 Vercel 作后备（未接）。平台给的预览地址在国内网络打不开，要用自己的域名访问。环境变量与 `.env.example` 同名；密钥只配在平台上，不进仓库。

解析接口有两条线路，网页先走北京、不通自动换新加坡：

- **北京**（首选）：火山引擎函数服务（华北2，与模型同机房），经 API 网关的默认域名访问。国内手机实测一句约 1.1 秒。更新：`node tools/build-cn-func.mjs` 生成 `cn-func/yanchu-parse.zip`，在函数控制台上传后发布；函数的环境变量配 `ARK_API_KEY`、`ARK_MODEL`。
- **新加坡**（后备）：网站自带的 `/api/parse`。服务器在境外，调北京的模型要跨境，白天也常超过 4 秒。

`/probe.html` 是线路测速页，在手机上打开能比较两条线路的耗时。
