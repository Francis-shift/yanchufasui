# 言出法随

说一句中文就能施法的 3D 守关游戏。打字（之后也能说话）说出咒语，大模型听懂这句话，程序按规则裁决，物理引擎让结果真实地发生。不想打字的人，用开局选的三个天赋按钮也能玩；给按钮写一句咒（或让模型看着局面帮你写），按钮就变成这一招。

> 傀儡大军从云海里沿石阶和索桥攻上山门。你是守山门的修士，身后是护山大阵的阵眼，阵眼破了就输。

首页是一张"活的封面"：背后就是山门场景，镜头慢慢摆，施法者自己放法术打碎上山的小傀儡，冰龙隔一阵飞下来；左边竖排书法标题加红印，点「试炼」或「守关」再选天赋、开始。首页主推的是**试炼模式**（守关排在第二个按钮）：在同一片广场上走位，躲 boss 的砸地红圈、扇形横扫、追踪冰锥和旋转弹幕，清掉它召来的小傀儡；小怪潮里除了追人自爆的小傀儡，第 2 段起有站在远处射紫火球的符箓傀儡，第 3 段起有地上亮红条后直线冲锋、冲完发晕的铁头傀儡；闪避花精力（3 格，慢慢回），踩着招落下的那一瞬闪开是完美闪避（顿帧、回法力和精力）；第一个 boss 寒甲傀儡王披着冰甲，只怕火；第二个石甲巨像披着石甲，只怕雷，会落石雨、一线地刺和蓄力冲撞（蓄力时猛打能打断，打断了它会硬直）；第三个火灵裹着火罩，只怕冰，会撒满场火圈、放追踪火球、推带缺口的火环（跑进缺口，或者迎着火环闪过去），狂暴时推一道火浪。一局是小怪潮与三个 boss 交替，开局只会本命招，每打完一段三选一学字——换按钮的招、字诀（写进按钮咒语里才生效，如「破」打甲翻倍、「随」追着打、「返」土墙把冰锥弹回 boss、「引」闪电劈碎冰锥）、领悟两个元素合成一招、心法（八个被动，如完美闪避后全场慢放、下一招加伤、闪避处留残影引走冰锥），打完 boss 还可能领悟"怎么召龙"（双龙：一次召两条，分扑两群；护身：龙绕着自己转，打碎碰到的冰锥、撞伤靠近的敌人）。战前给按钮写咒，战中只按键；手机上横过来玩，左手摇杆、右手按钮。打完（或倒下）结算用时、完美闪避次数、这一局发现了几种法术和本机最佳（存在这台设备的浏览器里）；倒下时写明止步于哪一段、那一段该怎么打。

## 一句话架构：模型管语义，程序管规则

```
玩家一句话
  → 回车 0.1 秒内：关键词先猜元素，法阵变色（不等网络）
  → 咏唱（最短 0.8 秒，时间慢到 0.3 倍）同时请服务器上的模型解析
       模型只输出固定格式的"法术意图"：元素、形态、目标、威力、颗数、轨迹、来源原词、气势、名字
       4.5 秒没回来 / 断网 / 额度用完 → 改用关键词解析，照样能玩
  → 清洗（game/rules/intent.js）：枚举不在表里就丢、数值夹到上限、来源词必须真在原话里
  → 裁决（game/rules/arbiter.js，纯函数）：消耗、组合八折、法力不够就降级、伤害、气势、首次发现、融合（先风后火 = 火卷风，先火后风 = 豪火灭却）、召唤（气势槽满才召得出龙，按钮召哪条看槽里哪种颜色多，打字可以点名；差一口气就化作同元素的雨）
  → 锁定：被打的敌人头上、落点地面先亮标记（亮的就是要打的）
  → 咒语卡：书法大字写名字；原话里被听懂的词加下划线并注明变成了什么，没听懂的标灰
  → 执行：弹 / 爆 / 墙 / 雨 × 火 / 冰 / 风 / 土 / 雷，冻结、灼烧、风推下悬崖、土墙挡路、雷连锁与麻痹；命中结算再走一遍规则（反应、盾牌减伤）
  → 敌人：上了广场按流场寻路，绕开香炉、华表、土墙，障碍一变就重算
```

模型说"威力 999"也只按上限算；会影响胜负的数字只在 `game/rules/` 里算，并有单元测试。

## 本地运行

需要 Node.js 20.9 以上。

```bash
npm install
cp .env.example .env.local   # 填入火山方舟的 API Key 与模型名；不填也能玩（只走关键词解析）
npm run dev
```

打开 http://localhost:3000 。按 <kbd>`</kbd> 打开调试面板（帧率、粒子数、上一句的解析来源与耗时）。

```bash
npm test                       # 规则层与防刷的单元测试
npm run build                  # 生产构建
python tools/build_preview.py  # 生成 preview/index.html（离线单文件，只走关键词解析）
```

## 部署

线上地址：https://www.yanchufasui.top （国内手机流量、微信内都能打开）。

部署在 EdgeOne Makers（原名 Pages；加速区域选"全球可用区（不含中国大陆）"，免备案）+ 自己的域名，推送到 main 即自动构建；同一仓库接 Vercel 作后备（未接）。平台给的预览地址在国内网络打不开，要用自己的域名访问。环境变量与 `.env.example` 同名；密钥只配在平台上，不进仓库。

解析接口有两条线路，网页先走北京、不通自动换新加坡：

- **北京**（首选）：火山引擎函数服务（华北2，与模型同机房），经 API 网关的默认域名访问。国内手机实测一句约 1.1 秒。更新：`node tools/build-cn-func.mjs` 生成 `cn-func/yanchu-parse.zip`，在函数控制台上传后发布；函数的环境变量配 `ARK_API_KEY`、`ARK_MODEL`，语音识别另配 `ASR_API_KEY`（或旧版控制台的 `ASR_APP_ID` + `ASR_ACCESS_TOKEN`）。
- **新加坡**（后备）：网站自带的 `/api/parse`。服务器在境外，调北京的模型要跨境，白天也常超过 4 秒。

`/probe.html` 是线路测速页，在手机上打开能比较两条线路的耗时。
